# 竹南冷凍公司－倉儲管理系統 2.0

依產品計畫書與技術方案建立的可操作 Demo。支援兩倉庫批次庫存、進貨、FIFO 出貨、盤點差異調整、報廢、異動查詢及基本資料新增。

## 啟動

需求：Node.js 22.5 或更新版本（本專案使用內建 `node:sqlite`，不需安裝 npm 套件）。

```powershell
npm start
```

瀏覽器開啟 <http://localhost:3000>。首次啟動會建立 `data/warehouse.sqlite` 並植入 Demo 資料；之後資料會保留在本機 SQLite 資料庫。刪除該資料庫再啟動即可重新建立乾淨的 Demo 資料。

可用 `PORT` 與 `DB_PATH` 環境變數指定埠號和資料庫位置。

## 預載資料

- W01 竹南冷凍倉庫1：甘藍菜 5 箱、高麗菜 8 箱、青江菜分成 A02 的 3 箱與 A05 的 5 箱兩個批次。
- W02 竹南冷凍倉庫2：甘藍菜 4 箱、青江菜 5 箱、玉米 6 箱。
- 商品單位為箱；初始批次日期刻意早於當日進貨，供 FIFO 操作展示。

## 操作流程

1. 在總覽或庫存總覽確認兩個倉庫與青江菜批次。
2. 進貨頁新增 2 箱甘藍菜至 W01 的 A01（甘藍菜在 W02 則使用 B01）。儲位選單會依倉庫與商品過濾，後端也會再次驗證。
3. 盤點頁建立 W01 盤點單，逐批輸入實際數量並確認；若在 A04 輸入 1 箱差異，系統會留下盤點調整記錄。
4. 報廢頁選取甘藍菜的批次，登記 1 箱、原因「腐爛」。
5. 出貨頁選擇青江菜與數量後，系統合併兩座倉庫庫存並按最早進貨時間排序產生搬運單；依單列倉庫與儲位取貨，逐批掃描外箱標籤並核對箱數。勾選搬運單完成後才可出貨，系統會留存搬運單及批次明細，並再次核對庫存批次未變動。
6. 在異動紀錄與庫存總覽核對結果。

首頁倉庫庫存概況可用商品選單篩選，並提示目前篩選商品最早進貨的倉庫與儲位。列表按商品分組、同商品最新進貨列在最上方，並用不同底色區分批次。進貨時間欄位預設為現在，員工可按進貨單修改；刪除誤登進貨會移除其目前剩餘庫存、隱藏原進貨紀錄並留下撤銷紀錄。每個倉庫內、每種商品僅最新進貨顯示「新進貨」備註。盤點步驟是「輸入實際數量」。要重現「甘藍菜實際 7 箱、其中 1 箱腐爛」的劇本，可先把盤點實際數量設為 7（不調整數量），再以報廢頁記錄腐爛的 1 箱。

每個儲位可在「基本資料」設定箱數上限；庫存以該儲位內所有商品合計計算。標準上限為 20 箱，新建儲位也預設 20 箱。進貨選單會顯示已滿或剩餘容量，後端也會在交易中再次檢查，避免同時進貨造成超量。

冷凍庫盤點建議採短進短出：入庫前在常溫區先按倉庫／走道／儲位整理清單，備妥手持掃描器、標籤、筆與保暖裝備；由庫外記錄員報位並登記，庫內員工只做快速目視、掃描或核數，不在庫內查系統、找資料或處理差異。依固定路線一次盤一區、合併同區工作，盤點差異回到庫外再查；庫外安排同伴確認進出與狀態、溫暖休息區、保暖手套與鞋衣，並依冷凍庫溫度、工作量和現場風險評估排定輪替與暖身休息。不要把單一分鐘數當成所有低溫和工作強度都適用的上限；主管機關／職安專業人員應依現場條件訂定工作休息安排。

## 技術與範圍

目前執行環境只有 Node.js，沒有既有程式、PostgreSQL 或安裝好的專案依賴。本 Demo 因此使用 Node.js 內建 HTTP 伺服器與關聯式 SQLite 資料庫，以免依賴外部服務仍可直接啟動、保存真實 CRUD 資料並展示交易流程。資料表、外鍵、檢查條件與交易皆在 `server.js`；前端為原生 HTML、CSS 與 JavaScript。SQLite 適合此單機 Demo，不等同於技術方案目標的多使用者 PostgreSQL 部署；正式多人使用前應遷移至 PostgreSQL，並補上登入、權限、備份與併發部署設定。

操作人員目前以單一 Demo 使用者「李太太」記錄。系統不包含帳號登入、正式庫存匯入、主檔停用/編輯或多裝置併發部署。
